Refactoring plan

src/main.rs is 202 lines, and main is 118 of them doing five unrelated jobs. The Write and Bash tool stages are next — this is the shape that makes them cheap instead of painful.

Ranked by payoff

01

Split into modules

→ new files alongside src/main.rs

No mod.rs needed — mod wire; in main.rs picks up src/wire.rs.

The win is that agent.rs becomes readable as the algorithm, with protocol noise living somewhere else. Everything below is easier once there are places to put things.
02

Co-locate each tool's schema with its implementation

→ src/main.rs:116 (schema) and src/main.rs:47–81 (executor)

Seventy lines apart today. One module exposing specs() and execute(), adjacent.

This is the defect the file is most likely to grow. Adding Write means editing two distant places, and nothing stops you from advertising a tool you haven't implemented — or implementing one you never advertised. The compiler can't catch either.
03

Message constructors

→ src/wire.rs

wire::user(prompt) and wire::tool_result(&call, &output). Three-line functions.

The loop body then reads as intent rather than JSON assembly, and it gives the role / tool_call_id details you learned the hard way exactly one home.
04

Stop using JSON as your internal type

→ src/main.rs:47–58, read_file_tool

It returns {"ok": bool, "content"|"error"} — a hand-rolled Either. Model it as Result<String, String> or a small ToolOutput enum, and serialize to that JSON shape only where you build the tool message.

Stringly-typed pokes like result["error"].as_str() disappear from the loop, and the pure functions become trivially testable. Keep the wire format exactly as it is — the model benefits from seeing {"ok":false,"error":…} — just don't carry it around in memory.
05

Make failures exit non-zero

→ src/main.rs:156 and src/main.rs:163

Both do eprintln! then return Ok(()), so a malformed response or an empty choices array exits 0. main already returns Box<dyn Error>, so return Err("no choices in response".into()) is enough.

The tester checks exit code. Today a bug in either path looks like a wrong-output failure rather than an error, which is a bad way to spend an evening. thiserror is overkill at this size.
06

Tests for the pure parts

→ src/tools.rs, src/wire.rs

execute_tool_call and the message constructors need no network and no client. A #[cfg(test)] mod tests with tempfile covers the Read cases — success, missing file, malformed arguments.

The item most likely to be skipped and most likely to be regretted. It pays for itself the first time a later stage breaks something you thought was settled.

Defer

Not yet

A trait Tool with a Vec<Box<dyn Tool>> registry. Scala instincts will want it, and it's probably where this ends up — but with one tool it's speculative. Wait until Bash lands and you have three. By then you'll know whether tools need state (working directory, permission prompts, output truncation), and that determines whether trait objects or a plain enum is the right call.

Order of operations

01 modules → 02 tools → 03 constructors → 04 types → 05 exits → 06 tests

01 and 02 are really one operation — moving the tool code is what gives tools.rs its reason to exist. Each step keeps the tree compiling, same discipline as the 4a–4e sequence.
